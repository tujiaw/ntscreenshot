# ntscreenshot UI 设计规范

## 设计原则

- 现代效率型：界面紧凑、层级清晰，避免装饰性渐变和过量卡片。
- 语义优先：业务代码使用颜色和组件角色，不直接写主题色值。
- 深浅一致：两个主题共享相同的信息层级、尺寸和状态，只替换语义颜色。
- 键盘友好：保留全局快捷键和已有键盘流，焦点状态必须清晰可见。

## 设计令牌

`ThemeTokens` 是唯一的 C++ 令牌来源，`ThemeManager` 将令牌同步到
`QPalette`、全局 QSS 和 Web CSS 变量。

| 类别 | 规范 |
| --- | --- |
| 字号 | 辅助 12px、正文 13px、副标题 15px、标题 18px |
| 间距 | 4 / 8 / 12 / 16 / 24px |
| 圆角 | 小 6px、中 10px、大 14px |
| 控件高度 | 紧凑按钮 32px、普通控件 34px、搜索框 48px |
| 图标 | 工具栏 18px，普通控件 16–18px |

颜色必须使用 `canvas`、`surface`、`surfaceSubtle`、`border`、
`textPrimary`、`textSecondary`、`accent`、`success`、`warning`、`danger`
等语义名称。禁止在新模块中复制具体深浅主题色值。

## 组件角色与状态

通过 `UiStyler::setRole()` 设置组件角色：

- `PrimaryButton`：当前流程的单一主要操作。
- `SecondaryButton`：保存、取消、恢复等次要操作。
- `GhostButton`：低强调文字操作。
- `DangerButton`：删除、停止等破坏性操作。
- `IconButton`：工具栏或标题栏图标操作。
- `Card`：需要边界的设置分组。
- `SearchField`：启动器式搜索输入框。

每个可交互组件必须具备 normal、hover、pressed、checked、focus、disabled
状态。不能仅依赖颜色表达成功、失败或选中状态；应同时提供文字、图标或边界变化。

## 首期界面规则

### 截图工具栏

- 工具按钮为 32×32px，图标为 18px。
- 使用真实 1px 分隔线划分样式、绘图、智能工具、截图输出和完成操作。
- “复制到剪贴板并完成”是主操作；保存是次操作。
- 文字型 OCR/GIF 与图标按钮保持相同点击区域和状态。

### 本地搜索

- 窗口根据工作区在 560–720px 之间自适应。
- 结果行使用“名称 + 路径 + 类型”两级层次，不使用斑马纹。
- 选中状态使用浅强调背景和左侧强调线，不使用整行高饱和蓝色。
- 页脚始终说明 `↑↓`、`Enter`、`Shift+Enter` 和 `<` 网络搜索。

### 设置

- 使用左侧一级导航，页面按常规、截图与输出、本地搜索、AI 助手、划词、HTTP 服务、路径记录、关于分组。
- 页面标题说明当前任务，原有表单字段、配置键和信号语义保持不变。
- 设置窗口基准尺寸为 840×560px，并继续使用项目的 DPI 缩放机制。
