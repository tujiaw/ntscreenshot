## 性能证据与边界

机器：Intel Core i5-14400，16 逻辑处理器，48 GiB 内存；Qt 6.8.3/MSVC Release。

build/browser-acceptance-final.log：23 步 1920×1080 高斯模糊重放 733 ms；万图枚举 1665 ms、首屏 1873 ms，期间 UI 心跳 180 次。10 次窗口开关的私有内存为 135、136、136、136、136、136、136、136、136、136 MiB。

素材旧流程的两次同步解码与当前两次缓存参数读取比较：4096×3072 为 94 ms 对 1300 ns；128×30000 为 35 ms 对 1100 ns。这仅比较参数读取阶段，当前首次后台解码仍有实际成本，不代表完整导入耗时降低到纳秒。

build/browser-acceptance-resources.log：整套测试每 50 ms 采样，峰值私有内存 409.4 MiB。单面板素材任务最多一个在途，已通过修订号与人工延迟完成的确定性测试；旧流程在 UI 线程直接解码，没有后台任务排队。

独立进程对比已完成：每组 3 次，10 ms 采样，使用同一套 Release 图像实现与相同输入；旧流程复现提交和应用时的两次同步解码，新流程使用面板实际异步导入和缓存读取。两份操作快照在测量末尾保留 600 ms，确保采样覆盖存活数据。原始记录为 build/material-memory-comparison.json，探针源码与可执行文件在 build/cmake-x64-Release/material-memory-probe.*。

| 输入 | 旧流程峰值私有内存范围 | 新流程峰值私有内存范围 | 首次就绪时间（旧／新） | UI 心跳（旧／新） |
| --- | --- | --- | --- | --- |
| 4096×3072 | 106.73–107.02 MiB | 58.70–58.76 MiB | 107–120／214–250 ms | 0／21–24 |
| 128×30000 | 39.82–40.15 MiB | 24.93–25.09 MiB | 51–55／181–187 ms | 0／17–18 |

新流程首次就绪时间包含 150 ms 防抖等待；优化收益是消除 UI 同步阻塞、避免重复解码和降低素材快照内存，不是宣称首次导入更快。旧流程没有后台队列但阻塞 UI；新流程每面板最多一个在途任务，修订号测试验证旧结果不会覆盖新选择。
