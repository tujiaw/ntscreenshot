# 图片浏览窗口产品级优化设计

日期：2026-11-20

## 目标与边界

面向截图查看、轻量编辑和导出的日常使用者，将现有图片浏览窗口提升为可稳定交付的产品。覆盖目录浏览、缩放平移、动画、九类编辑工具、撤销重做、保存转换、系统背景、键盘操作和中英文提示。以正确性、文件安全、响应速度和结果可预期为验收依据。保留 Qt/OpenCV 技术栈；不新增云端服务或专业图层编辑器。

## 方案比较

1. 沿用现有模块并分阶段加固（实施建议）：已有文档、测试及异步加载和原子写入基础，可对具体缺陷建立回归证据，控制迁移风险。
2. 重写窗口及编辑状态管理：统一程度较高，但会同时改动成熟交互、引入广泛回归，当前没有证据证明必须重写。

本设计采用方案 1，由实施者决定；用户已明确授权自主推进，不再要求选择技术方案。

## 行为要求

### 浏览与文件安全

目录扫描、缩略图和主图加载不得让过期结果替换当前选择。快速切图、刷新、目录变化及关闭窗口均应保持状态一致。损坏、不可读、超大图片应提供明确提示与安全限制。保存失败保留编辑结果；覆盖原图必须确认并检查外部修改。删除使用现有安全路径，取消不得改变选择与编辑状态。

### 编辑与导出

逐项验证裁剪旋转、标注、透视、马赛克、水印、素材、滤镜、调色及抠图的边界、取消和撤销重做。连续调参合并为合理的撤销步骤，切换工具不意外提交未完成绘制。耗时处理期间的后续操作只能作用于正确的图片和编辑版本。保存与格式转换须明确区分继续编辑和导出，不能因导出丢失可恢复的编辑状态。格式、尺寸、透明度及动画当前帧行为应与提示一致。

### 响应与交互

主线程避免重型解码和图像处理。审查长编辑链的重放成本、任务排队及内存生命周期；优化必须建立在测量或可复现问题上。缩放锚点、选区坐标、画笔尺寸和窗口布局在不同 DPI 下保持一致。常用操作可通过键盘完成，禁用状态、进度、错误和中英文文案一致。

## 实施顺序与验证

1. 运行现有图片浏览测试并检查相关实现，建立缺陷与覆盖清单。
2. 优先修复文件安全和异步状态问题，每项补充能复现用户后果的回归测试。
3. 验证并完善编辑工具、导出状态及长编辑链性能。
4. 验证缩放、键盘、布局和中英文提示，更新用户文档。
5. 执行构建、图片浏览测试和仓库必要检查，并对可运行环境做窗口操作验证。

完成证据应包含实际命令与结果、人工操作覆盖及已知限制。自动测试通过不能单独证明经得起市场考验；无法在当前环境验证的部分须明确记录，不宣称完成。

## 待实施者确定

具体缺陷修复方式、缓存与任务调度细节在复现和测量后决定。任何新增用户功能或破坏既有习惯的交互变更均需在实现前明确说明。提交信息采用简短的 Conventional Commits 格式。

## 审阅补充的验收边界

- 另存为：切换到新文件并建立新的编辑基线。格式转换：所有目标格式均作为导出，保留源文档、脏状态及撤销记录；这是对当前仅 PDF 保留历史行为的统一调整，需随本设计确认。
- 结果质量：覆盖 EXIF 方向、ICC 色彩配置、透明边缘及 JPEG 有损输出；保存后的显示应反映实际编码结果。
- 删除失败或回收站不可用时保留原图，禁止自动降级为永久删除。
- 性能：固定代表性的大图、长截图和长编辑链，比较优化前后的加载与调参耗时、峰值内存和任务排队长度；记录机器配置与样本尺寸。具体阈值根据基线测量确定，不将未测量的流畅性作为完成证据。
